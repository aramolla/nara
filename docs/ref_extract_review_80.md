# 항 단위 조문 참조 추출 80건 테스트

50건 테스트 후 아래를 바꾸고, 항 30개(51~80번)를 더해 80건으로 실행한 결과. 1~50번 입력은 `docs/ref_extract_review_50.md`와 같다.

- 모델: google/gemma-4-26B-A4B-it (int8_per_channel_weight_only, max_model_len 16384)
- 추론: 20.0s (80건 배치), 80건 모두 `finish=stop`, 최종 스키마 검증 통과
- 51~80번 선정: 21~50번과 같은 방식(문서별 균등 무작위, seed 7), 1~50번과 겹치지 않게. 참조가 없는 항 3개 포함.
- 약칭 사전은 아직 없다.


## 50건 이후 바꾼 것

| 변경 | 내용 |
|---|---|
| `expression`에 법령 표시 포함 | 번호 앞의 「X」, 법, 영, 같은 법 등(사이의 괄호 포함)까지 복사. 파서(`split_prefix`)는 표시를 떼고 번호만 읽음 |
| 표시 없으면 현재 법령 | `expression`이 번호로 바로 시작하면 코드가 `law`를 null로 확정 (LLM 판단 무시). 프롬프트에도 같은 규칙 추가 |
| 조문이 아닌 번호 제외 | 별지 서식, 부칙 조문, 법령 공포 번호(대통령령 제N호 등)를 프롬프트와 코드(`not_article_ref`)에서 제외 |


## 요약

| 기준 | 결과 |
|---|---|
| 참조 표현 찾기 | 80/80 ✅ (참조 없는 항 7개 모두 빈 목록) |
| 조·항 번호 | 80/80 ✅ |
| 법령 판별 | 75/80. 오답 5건은 모두 예규 약칭 |

- 50건 때 LLM 판별 오류였던 [23]("「국가재정법」 제6조 … 또는 제6조")이 해결됐다. 두 번째 "제6조"는 표시가 없어 코드가 null로 확정.

- [11](집행기준, "시행령", "시행규칙")은 이번에 LLM이 국가계약법 시행령·시행규칙으로 맞췄지만, 같은 문서의 [42]는 지방계약법으로 틀렸다. 추측이라 일관되지 않다.
- 약칭 사전으로 해결할 예정.


## 기타

- [11]에서 LLM이 `law`에 「」까지 적었다 ("「국가를 당사자로 하는 계약에 관한 법률 시행령」"). 실행 후 코드에서 「」를 떼도록 고쳤다 (재실행 전).
- LLM이 번호 없는 표현을 3건 추출했다: "대통령령"([53]), "대통령령으로 정하는 사유"([56]), "「민법」"([69]). 파서가 번호를 못 찾아 결과에서 빠졌으므로 최종 결과에는 영향 없음.
- 원문 위치를 못 찾은 표현 2건([14] ","→"ㆍ", [37] 띄어쓰기). 결과는 맞음.


## 약칭 사전 적용

- `prep/build_abbrev.py` → `model/abbrev.json`: 원문에 명시된 정의 「X」(이하 "Y"라 한다)만 문서별로 추출 (문서 15개, 약칭 27개).
  - 제외: 범위 제한 정의 1건(집행기준 "이하 이 장에서 "법""), 같은 약칭을 다르게 정의한 1건(낙찰자 결정기준 "낙찰자결정기준"), 「」 없는 정의, 정의 없이 쓰는 약칭.
- `assemble`: `expression`의 법령 표시가 해당 문서 사전의 약칭이면 `law`를 사전의 정식 이름으로 바꾼다 (LLM 판단 무시).
- 프롬프트는 바꾸지 않았으므로, 80건 실행의 LLM 출력을 그대로 다시 조립해 확인했다.

| # | 적용 전 | 적용 후 |
|---|---|---|
| 11 | 「국가계약법 시행령」 등 (「」 포함) | 국가계약법 시행령, 국가계약법 시행규칙 ✅ |
| 41, 51, 71 | "공동계약운용요령 시행령" | 국가계약법 시행령 ✅ |
| 42 | 지방계약법 시행령 | 국가계약법 시행령 ✅ |
| 21 | "법률", "시행령" | "법률" ❌, 국가계약법 시행령 ✅ |

결과: 80건 중 79건 정답. 남은 [21]의 "법률"은 공동계약운용요령에 정의가 없는 약칭이라 사전에 넣지 않았다.
